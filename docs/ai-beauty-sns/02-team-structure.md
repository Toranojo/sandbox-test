# チーム体制：AI美女 × SNS × note 運用

`01-operation-guide.md` のSTEP①〜⑥を回すためのエージェントチーム編成。1人が複数役を兼任してもよいが、責務は分離して管理する。

## チームリーダー（プロジェクトリード）

**責務**
- 全体戦略（誰に見せる→何を発信→どんな悩みを解決→どこで収益化）の設計と維持
- 週次の進行管理、各担当のアウトプットの最終承認
- コンプライアンス最終チェック（本README記載のNGルールの遵守を担保）
- KPIのモニタリングと方針転換の意思決定

**成果物**：週次運用方針、優先タスクの采配、公開前の最終ゴーサイン

---

## 各エージェントの役割

| # | 役割 | 対応STEP | 主な責務 | 成果物 |
| --- | --- | --- | --- | --- |
| 1 | キャラクター設計担当 | STEP① | ペルソナ設計、プロフィール文、投稿テーマ10個以上の策定・更新 | キャラクター設計シート（`03-character-brief-template.md`使用） |
| 2 | プロンプト・画像生成担当 | STEP②③④ | 「6つの箱」プロンプトの作成、シーン量産、固定/変化要素の管理、複数枚生成 | シーン別プロンプト集、生成画像候補 |
| 3 | 画像QA担当 | STEP②④ | 手指・目線・歯・耳・背景文字・鏡反射のチェック、同一人物としての一貫性チェック、採用カットの選定 | QA済み画像リスト（採用/却下ログ） |
| 4 | コンテンツ・コピーライター | STEP⑤ | 日常・趣味・仕事目標・質問の4分類で投稿文を作成、ストーリー性の付与 | 投稿キャプション、note日記本文 |
| 5 | SNS/note運用担当 | STEP⑤ | 投稿スケジューリング、エンゲージメント対応（コメント・質問への返信）、note公開・有料設定 | 投稿カレンダー、公開スケジュール |
| 6 | 収益化・オファー設計担当 | STEP⑥ | ターゲット×発信テーマ×収益導線の設計、note有料マガジン/記事の価格・特典設計 | マネタイズ導線図、オファー内容 |
| 7 | コンプライアンス／リスク管理担当 | 全STEP | 実在人物との類似性チェック、年齢表記の明確化、性的表現の逸脱防止、虚偽体験談の防止 | 公開前チェックリスト、是正指示 |

> 小規模チームの場合：1〜7を「制作（1〜3）」「発信（4〜5）」「収益・監査（6〜7）」の3人体制に統合可能。ただし**コンプライアンス担当の承認は必ず独立した最終関門として残す**こと。

## ワークフロー（パイプライン）

```
[キャラクター設計担当]
    │ キャラクター設計シート確定
    ▼
[プロンプト・画像生成担当]
    │ シーン別プロンプトで複数枚生成
    ▼
[画像QA担当]
    │ 手指/目線/歯/耳/背景/反射チェック・一貫性チェック → 採用カット確定
    ▼
[コンテンツ・コピーライター]
    │ ストーリー＋質問付きキャプション作成
    ▼
[コンプライアンス担当]
    │ 公開前チェックリストで最終確認
    ▼
[SNS/note運用担当]
    │ 投稿・公開、エンゲージメント対応
    ▼
[収益化・オファー設計担当]
    │ 有料note・導線の効果測定 → 改善提案
    ▼
[チームリーダー]
      週次レビュー・方針更新（①へフィードバック）
```

## 公開前チェックリスト（コンプライアンス担当が最終承認）

- [ ] キャラクターが実在の人物・有名人に似ていないか
- [ ] 成人であることが明確に分かる設定・見た目になっているか
- [ ] 過度な露出・性的表現になっていないか（有料部分の水着等カットは、雑誌グラビア・水着カット程度に留まり、ヌード・性的行為を想起させる構図になっていないか）
- [ ] 際どめのカットを投稿する場合、投稿先プラットフォーム（note・X等）の利用規約に抵触しないか確認したか
- [ ] 架空の体験談で商品・サービスを紹介していないか（ステマ的表現の有無）
- [ ] 画像の手指・目線・歯・耳・背景の破綻がないか
- [ ] 同一キャラクターとして一貫性（髪型・髪色・雰囲気）が保たれているか
- [ ] キャプションにストーリーと質問（エンゲージメント導線）が入っているか

## KPI（例）

- キャラクター認知：フォロワー増加数、投稿インプレッション
- エンゲージメント：質問投稿への返信率・コメント数
- 収益：note有料記事/マガジンの購読数・売上、無料→有料の転換率
- 品質：画像QAでの却下率（低いほど生成プロンプトが安定している指標）
